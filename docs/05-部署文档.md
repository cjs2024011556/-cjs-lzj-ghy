## 一、部署概述

### 1.1 部署目标

| 项 | 值 |
|---|---|
| CPU 架构 | **龙芯 LoongArch**（loongarch64） |
| 操作系统 | **银河麒麟高级服务器 V11 / V10** |
| 模型来源 | **阿里云百炼平台**（DashScope） |
| 部署方式 | Docker Compose + systemd + Nginx |
| 访问方式 | B/S 架构，浏览器访问 |

### 1.2 系统架构（部署视图）

```
                    [用户浏览器]
                          ↓ HTTP/HTTPS
                    [Nginx 80/443]
                          ↓ 反向代理
                    [FastAPI 8000] (uvicorn, 2 workers)
                          ↓
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
   [PostgreSQL]      [Milvus]         [MinIO]
      5432            19530            9000
                          ↓
                    [Neo4j]  (可选)
                      7687
```

### 1.3 网络与端口

| 服务 | 端口 | 内部/外部 | 备注 |
|---|---|---|---|
| Nginx | 80, 443 | 外部 | 用户访问 |
| Backend | 8000 | 内部 | 反向代理 |
| PostgreSQL | 5432 | 内部 | |
| Milvus | 19530 | 内部 | |
| Neo4j | 7474, 7687 | 内部 | |
| MinIO | 9000, 9001 | 内部 | 9001 是 Console |

## 三、软件依赖

### 3.1 系统包

```bash
# 银河麒麟（基于 RHEL 系）
sudo yum install -y \
  python3.11 python3.11-devel python3-pip \
  nodejs npm \
  git curl wget \
  nginx \
  postgresql postgresql-contrib \
  java-17-openjdk   # Neo4j 需要
```

### 3.2 Docker 与 Docker Compose

```bash
# 麒麟 V11
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo yum install -y docker-ce docker-ce-cli containerd.io
sudo systemctl start docker
sudo systemctl enable docker

# Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
```

### 3.3 Python 依赖

详见 `backend/requirements.txt`。注意：
- 部分包在 LoongArch 上需要找对应架构的 wheel
- 推荐使用 conda-forge 的 loongarch64 通道

### 3.4 阿里云百炼 API Key

1. 访问 https://bailian.console.aliyun.com/
2. 注册 / 登录阿里云账号
3. 开通"百炼"服务
4. 创建 API Key（推荐用子账号 + RAM 策略）
5. 充值或申请试用额度

## 四、部署步骤

### 4.1 一键部署（推荐）

```bash
# 1. 上传项目代码到 /opt/a1
sudo mkdir -p /opt/a1
sudo chown $USER:$USER /opt/a1
cd /opt/a1
# 上传或 git clone 项目代码

# 2. 配置环境变量
cp .env.example .env
vim .env
# 填入 DASHSCOPE_API_KEY=sk-xxx
# 其他配置按需调整

# 3. 执行一键脚本
chmod +x deploy/install.sh
sudo bash deploy/install.sh

# 4. 验证
curl http://localhost:8000/api/v1/health
```

### 4.2 手动部署（详细步骤）

#### 4.2.1 准备项目目录

```bash
sudo mkdir -p /opt/a1
sudo chown $USER:$USER /opt/a1
cd /opt/a1
# 假设项目已上传到当前目录
```

#### 4.2.2 配置环境变量

```bash
cp .env.example .env
nano .env
```

关键配置项：
```bash
# 必填：百炼 API Key
DASHSCOPE_API_KEY=sk-your-key-here

# 模式选择
LLM_MODE=cloud    # 默认走云端

# 数据库密码
POSTGRES_PASSWORD=your-strong-password
NEO4J_PASSWORD=your-neo4j-password
MINIO_SECRET_KEY=your-minio-password
```

#### 4.2.3 启动基础服务

```bash
cd /opt/a1
sudo docker compose up -d postgres milvus-standalone neo4j minio

# 等待服务就绪（约 30-60s）
sleep 30
sudo docker compose ps
```

#### 4.2.4 安装后端

```bash
cd /opt/a1/backend
python3.11 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

#### 4.2.5 安装前端

```bash
cd /opt/a1/frontend
npm install
npm run build
# 产物在 dist/
```

#### 4.2.6 注册后端服务

```bash
sudo cp /opt/a1/deploy/a1-backend.service /etc/systemd/system/
sudo mkdir -p /var/log/a1
sudo chown a1user:a1user /var/log/a1   # 或 root，看 service 配置
sudo systemctl daemon-reload
sudo systemctl enable a1-backend
sudo systemctl start a1-backend
sudo systemctl status a1-backend
```

#### 4.2.7 配置 Nginx

```bash
sudo cp /opt/a1/deploy/nginx.conf /etc/nginx/conf.d/a1.conf
sudo nginx -t
sudo systemctl restart nginx
```

#### 4.2.8 导入内置数据

```bash
cd /opt/a1/backend
source .venv/bin/activate
python -m scripts.import_sample_data
```

或通过 API：
```bash
curl -X POST http://localhost:8000/api/v1/knowledge/import/all
```

#### 4.2.9 验证

```bash
# 健康检查
curl http://localhost:8000/api/v1/health
# 预期: {"status":"ok",...}

# 访问前端
curl http://localhost/
# 预期: HTML 页面

# 浏览器访问
http://<服务器IP>
```

### 5.2 Python 包适配

部分包在 LoongArch 上可能没有官方 wheel，处理方式：

1. **优先**：使用 conda-forge 通道
   ```bash
   conda install -c conda-forge pytorch transformers
   ```

2. **备选**：使用 loongarch64 社区 wheel
   ```bash
   pip install --index-url https://pypi.loongnix.cn/simple/ <package>
   ```

3. **最差**：从源码编译
   ```bash
   pip install --no-binary :all: <package>
   ```

## 六、生产环境建议

### 6.1 安全

1. **修改默认密码**
   - PostgreSQL
   - Neo4j
   - MinIO

2. **启用 HTTPS**
   - 申请 SSL 证书（Let's Encrypt）
   - 修改 Nginx 配置

3. **防火墙**
   ```bash
   sudo firewall-cmd --permanent --add-service=http
   sudo firewall-cmd --permanent --add-service=https
   sudo firewall-cmd --reload
   # 仅开放 80/443，数据库端口不对外
   ```

4. **密钥管理**
   - 不要把 API Key 提交到 Git
   - 用环境变量或 secret 管理

### 6.2 监控

1. **进程守护**
   - systemd 已配置自动重启
   - 健康检查端点 `/api/v1/health`

2. **日志**
   - 应用日志：`/var/log/a1/backend.log`
   - 错误日志：`/var/log/a1/backend-error.log`
   - Nginx 日志：`/var/log/nginx/`

3. **资源监控**（可选）
   - Prometheus + Grafana
   - node_exporter

### 6.3 备份

```bash
# PostgreSQL 备份
docker exec a1-postgres pg_dump -U a1_user a1_maintenance > backup_$(date +%Y%m%d).sql

# MinIO 数据备份
rsync -av /opt/a1/backend/data/minio/ /backup/minio/

# 配置文件备份
cp /opt/a1/.env /backup/env_$(date +%Y%m%d)
```

### 6.4 升级

```bash
# 1. 拉取新代码
cd /opt/a1
git pull  # 或重新上传

# 2. 重启服务
sudo systemctl restart a1-backend
sudo docker compose restart postgres milvus-standalone

# 3. 前端重新构建
cd frontend
npm run build
```

## 七、故障排查

### 7.1 后端无法启动

```bash
# 查看状态
sudo systemctl status a1-backend

# 查看日志
sudo journalctl -u a1-backend -n 100

# 常见原因
# 1. .env 配置错误 → 检查 DASHSCOPE_API_KEY
# 2. 端口占用 → sudo lsof -i :8000
# 3. 数据库未启动 → sudo docker compose ps
# 4. Python 依赖缺失 → pip install -r requirements.txt
```

### 7.2 数据库连接失败

```bash
# 检查 Docker
sudo docker ps
sudo docker logs a1-postgres

# 测试连接
docker exec -it a1-postgres psql -U a1_user -d a1_maintenance
```

### 7.3 模型调用失败

```bash
# 测试百炼 API
curl -X POST http://localhost:8000/api/v1/llm/test \
  -H "Content-Type: application/json" \
  -d '{"message":"hello"}'

# 查看错误
sudo journalctl -u a1-backend -n 50
```

### 7.4 前端 404

```bash
# 检查 Nginx 配置
sudo nginx -t
cat /etc/nginx/conf.d/a1.conf

# 检查前端构建产物
ls /opt/a1/frontend/dist/

# 重启 Nginx
sudo systemctl restart nginx
```
