## 一、项目概述

### 1.1 项目背景

在钢铁、汽车制造等大型产线场景下，设备密集且高度联动，单次非计划停机损失超过 100 万元。传统运维存在以下痛点：

1. **知识分散**：检修知识散落在设备手册、运行日志、老员工经验中，形成"数据孤岛"
2. **检索低效**：现场出现故障时，难以及时找到对应的解决方案
3. **作业不规范**：新人上岗慢，作业步骤依个人经验，合规风险高
4. **经验传承难**：老员工退休/离职后，经验无法有效沉淀

### 1.2 项目目标

开发一套基于多模态大模型技术的设备检修知识检索与作业辅助系统，破解上述痛点，实现：

- **检索智能化**：多模态输入（文本/图像/设备型号）→ 精准跨模态语义匹配
- **作业标准化**：基于设备类型 + 检修等级的步骤化 SOP + 合规校验
- **知识可沉淀**：一线人员上传案例 → 审核 → 入库 → 检索的闭环
- **部署国产化**：在龙芯 LoongArch + 银河麒麟 V11/V10 上完整运行

### 1.3 适用范围

- 行业：钢铁、汽车制造等大型产线
- 用户：一线检修作业人员、设备工程师、车间主管
- 设备类型：通用工业设备（液压系统、电机、阀门、泵等）
- 部署环境：龙芯 LoongArch + 银河麒麟 V11/V10

## 二、用户角色与场景

### 2.1 用户角色

| 角色 | 描述 | 典型操作 |
|---|---|---|
| **一线检修工** | 现场作业人员 | 拍照查询、检索方案、执行 SOP、上报案例 |
| **设备工程师** | 负责设备维护与方案设计 | 编写 SOP、审核案例、查询历史数据 |
| **车间主管** | 统筹车间运维 | 看板监控、批量审核、人员管理 |
| **系统管理员** | 维护系统 | 用户管理、知识库维护、模型切换 |

### 2.2 典型场景

**场景 1：现场故障快速诊断**
- 一线人员发现液压系统压力异常
- 拍照 + 输入"压力低" → 系统返回相关案例和可能原因
- 根据推荐方案执行处理

**场景 2：新人规范化作业**
- 新人首次独立检修电机
- 选择"电机 + 二级保养" → 系统输出 12 步标准化 SOP
- 每步有工具/风险/合规点提示

**场景 3：经验沉淀**
- 老师傅处理完一次特殊故障
- 上传故障描述 + 处理过程 + 照片
- 工程师审核通过 → 进入知识库 → 下次类似问题可被检索到

## 三、功能需求

### 3.1 F1: 可视化界面（30% 评分项 · 功能完整性）

#### 3.1.1 需求描述
- 系统提供 PC Web 可视化界面（响应式，兼容平板）
- 用户可访问：登录页、首页 Dashboard、多模态检索页、作业指导页、知识管理页、后台审核页
- 界面美观大方，工业风（深色高对比）

#### 3.1.2 详细功能

| 编号 | 功能 | 优先级 |
|---|---|---|
| F1.1 | 登录/登出 | P0 |
| F1.2 | 首页 Dashboard（统计、最近活动） | P0 |
| F1.3 | 顶部导航 + 侧边栏 | P0 |
| F1.4 | 多模态输入控件（文本/图像/设备型号） | P0 |
| F1.5 | 步骤化 SOP 卡片展示 | P0 |
| F1.6 | 知识图谱可视化 | P2 |
| F1.7 | 响应式布局（PC/平板） | P0 |
| F1.8 | 错误页 / Loading / 空状态 | P1 |

#### 3.1.3 验收标准
- 在 Chrome / Edge 浏览器可正常访问
- 1920×1080 主流分辨率下布局合理
- 关键操作（检索/查询 SOP）≤ 3 次点击完成

---

### 3.2 F2: 多模态知识检索（30% 评分项 · 功能完整性）

#### 3.2.1 需求描述
- 支持文本、故障图片、设备型号等多种输入
- 实现精准语义检索与跨模态匹配
- 快速调取检修手册等资源
- 返回带引用溯源的答案

#### 3.2.2 详细功能

| 编号 | 功能 | 优先级 |
|---|---|---|
| F2.1 | 纯文本检索 | P0 |
| F2.2 | 图像检索（以图搜文） | P0 |
| F2.3 | 设备型号精确匹配 | P0 |
| F2.4 | 跨模态混合检索（文本+图） | P0 |
| F2.5 | 答案引用溯源（标注来源） | P1 |
| F2.6 | 关键词 + 向量混合检索 | P1 |
| F2.7 | 重排序（Rerank） | P2 |

#### 3.2.3 验收标准
- 文本查询返回相关手册段落
- 上传故障图能匹配到相似案例
- 答案包含来源标注（手册名 + 章节）
- 检索响应 P95 < 5s

---

### 3.3 F3: 标准化作业指引（30% 评分项 · 功能完整性）

#### 3.3.1 需求描述
- 嵌入检修全流程
- 提供步骤化操作指引
- 合规校验提醒
- 根据设备类型与检修等级个性化推送流程

#### 3.3.2 详细功能

| 编号 | 功能 | 优先级 |
|---|---|---|
| F3.1 | 选择设备类型 + 检修等级 → 生成 SOP | P0 |
| F3.2 | 步骤化展示（编号、标题、操作、风险、工具） | P0 |
| F3.3 | 合规校验点（断电、挂牌、PPE 等） | P0 |
| F3.4 | 安全警告提示 | P0 |
| F3.5 | 步骤勾选 / 进度记录 | P1 |
| F3.6 | 故障描述 → 个性化重写 SOP | P1 |
| F3.7 | 完成后自动沉淀为案例 | P2 |

#### 3.3.3 验收标准
- 选择"液压系统 + 二级保养"返回 8-15 步 SOP
- 每步包含：动作、风险等级、工具、合规点
- 检修前显示安全警告
- 步骤可勾选记录完成情况

---

### 3.4 F4: 知识沉淀与更新（30% 评分项 · 功能完整性）

#### 3.4.1 需求描述
- 一线人员上传检修案例、经验总结
- 经审核后纳入知识图谱
- 实时更新知识库
- 支持手动标注与修正大模型输出

#### 3.4.2 详细功能

| 编号 | 功能 | 优先级 |
|---|---|---|
| F4.1 | 一线人员提交案例（文本+附件） | P0 |
| F4.2 | 管理员审核（批量/单个） | P0 |
| F4.3 | 审核通过后入库（向量化+入图谱） | P0 |
| F4.4 | 审核驳回 + 原因 | P0 |
| F4.5 | 用户对答案的反馈（评分+纠正） | P1 |
| F4.6 | 反馈数据用于模型优化（LoRA 微调） | P2 |
| F4.7 | 知识库版本管理 | P2 |

#### 3.4.3 验收标准
- 上传案例 → 进入"待审核"状态
- 审核通过后，该案例能通过检索召回
- 用户反馈数据持久化存储

## 四、非功能需求

### 4.1 NF1: 界面美观（20% 评分项 · 用户体验）
- 工业风设计（深色高对比）
- 统一色彩、字体、间距
- 现场场景适配（强光下可读、按钮适配手套操作）

### 4.2 NF2: 文档完整（20% 评分项 · 文档与演示）
- 需求分析文档（本文）
- 功能设计文档
- 产品说明书
- 测试报告
- 部署文档
- 源文件 + 演示 PPT + ≤7min 视频

### 4.3 NF3: 交互便捷（20% 评分项 · 用户体验）
- 拍照即可识别
- 语音输入
- 引导式操作（少输入、多点选）
- 错误友好提示

### 4.4 NF4: 易用性与稳定性（隐含）
- 后端 5xx 率 < 1%
- 前端首屏 < 2s
- 检索 P95 < 5s
- 异常有兜底，不崩溃

## 五、约束与限制

### 5.1 部署硬约束（0 分项）
- **架构**：B/S
- **CPU**：龙芯 LoongArch
- **OS**：银河麒麟 V11 / V10
- 不满足任一项：视为 0 分

### 5.2 模型约束
- **最终模型来源**：阿里云百炼平台（DashScope）
- **云端 API**：qwen-vl-max（默认）
- **本地降级**：Qwen2-VL-7B-Instruct（同源开源）

### 5.3 评分占比
- 功能完整性 30%
- 用户体验 20%
- 创新与实用性 20%
- 文档与演示 20%
- 商业可行性 10%
