## 一、系统概述

### 1.1 设计目标

A1 设备检修智能系统是一个基于多模态大模型技术的智能化辅助系统，专注于工业（钢铁/汽车制造等）产线设备检修场景。系统在**龙芯 LoongArch + 银河麒麟 V11/V10** 国产化平台上运行，使用**阿里云百炼平台**（DashScope）的多模态大模型，提供检索、作业指引、知识沉淀与更新等核心能力。

### 1.2 设计原则

1. **国产化优先**：所有技术栈均支持 LoongArch 架构与麒麟操作系统
2. **模型双模式**：默认走百炼云端 API，本地 Qwen2-VL-7B 作为降级
3. **知识驱动**：以知识图谱 + RAG 为核心，避免 LLM 幻觉
4. **闭环可观测**：用户反馈 → 持续优化
5. **工程化交付**：Docker 化、systemd 守护、健康检查

## 三、模块设计

### 3.1 模型适配层（双模式）

#### 3.1.1 设计目标
- 统一接口（`ModelAdapter` 抽象基类）
- 透明切换（配置驱动）
- 提示词兼容（同模型家族）

#### 3.1.2 接口设计

```python
class ModelAdapter(ABC):
    @property
    def mode(self) -> str: ...          # "cloud" | "local"
    @property
    def model_name(self) -> str: ...

    async def chat(self, request: ChatRequest) -> ChatResponse: ...
    async def embed(self, texts: List[str]) -> List[List[float]]: ...
    async def parse_document(self, file_path: str) -> str: ...
```

#### 3.1.3 切换流程

```
用户操作（API: POST /api/v1/llm/switch）
    ↓
factory.switch_mode("cloud" | "local")
    ↓
销毁旧 adapter 实例 + 创建新实例
    ↓
下次调用使用新 adapter
```

#### 3.1.4 配置

```yaml
# config.yaml / .env
LLM_MODE=cloud               # cloud | local
DASHSCOPE_API_KEY=sk-xxx
DASHSCOPE_MODEL=qwen-vl-max
LOCAL_MODEL_PATH=/opt/models/Qwen2-VL-7B-Instruct
LOCAL_MODEL_BACKEND=transformers
```

### 3.2 多模态检索服务（F2）

#### 3.2.1 数据流

```
用户输入（文本/图像/型号）
  ↓
[预处理]
  - 图像: 多模态 LLM 生成图像描述
  - 型号: 标准化（大小写、空格）
  ↓
[Embedding] BGE-M3 向量化
  ↓
[召回] Milvus 向量检索 Top-K=50
  ↓
[重排] 混合检索 (向量 + 关键词)
  ↓
[生成] 阿里云百炼 qwen-vl-max
       - 输入: 检索结果 + 用户问题
       - 输出: 带引用的答案
  ↓
返回: { answer, hits, model, latency_ms }
```

#### 3.2.2 跨模态匹配

- **以文搜图**：文本 query → embedding → 检索图像元数据
- **以图搜文**：图像 → LLM 描述 → embedding → 检索文本
- **文图混合**：拼接 embedding 后检索

#### 3.2.3 引用溯源

每条答案附带来源标注：
- 文档名（如 `液压系统检修手册.md`）
- 章节（如 `第 2.1 节`）
- 案例 ID（如 `CASE-2024-001`）

### 3.3 标准化作业指引服务（F3）

#### 3.3.1 数据源
- **内置 SOP 库**：`sop_library.json`（4 个标准 SOP）
- **LLM 个性化重写**：根据用户具体场景定制

#### 3.3.2 流程

```
用户输入: 设备类型 + 型号 + 检修等级 + 故障描述
  ↓
[查 SOP 库] 优先匹配内置 SOP
  ↓
[LLM 改写] 基于 SOP + 用户具体场景生成个性化指引
  ↓
[结构化输出] JSON: steps, tools, safety_warnings, compliance
  ↓
[前端展示] 步骤化卡片 + 勾选 + 进度条
```

#### 3.3.3 步骤结构

```json
{
  "step_no": 1,
  "title": "停机断电挂牌",
  "action": "按下急停按钮，断开主电源开关...",
  "risk_level": "high",
  "tools": ["扳手"],
  "compliance": ["断电", "验电", "挂牌", "上锁"],
  "estimated_minutes": 5
}
```

### 3.4 知识沉淀服务（F4）

#### 3.4.1 流程

```
一线人员提交案例 (POST /api/v1/knowledge/case/submit)
  ↓
状态: pending（待审核）
  ↓
管理员审核 (POST /api/v1/knowledge/case/review)
  ├─ 通过 → 触发 _index_case() 入库 Milvus
  └─ 驳回 → 状态 rejected + 原因
  ↓
用户反馈 (POST /api/v1/knowledge/feedback)
  ↓
数据用于: 1) 检索召回  2) LoRA 微调（可选）
```

#### 3.4.2 知识库管理

- **导入接口**：`POST /api/v1/knowledge/import/{manuals,cases,sops,all}`
- **统计接口**：`GET /api/v1/knowledge/stats`

## 七、性能与稳定性

### 7.1 性能指标
- 检索响应 P95 < 5s（含 LLM）
- 前端首屏 < 2s
- 后端 5xx 率 < 1%

### 7.2 稳定性措施
- 异常处理中间件
- 超时控制（LLM 60s, HTTP 120s）
- 健康检查 + 进程守护
- 日志分级（控制台 + 文件 + 错误单独）

### 7.3 降级策略
- 百炼 API 失败 → 自动重试 1 次
- 本地模型 OOM → 降级到 embedding-only
- Milvus 不可用 → 纯 LLM 模式
